# 3.5.4 — 2026-09-19

## Added

- **`createApp` declares `sessionMode: 'stateful'` and a `teardown` hook** ([#120](https://github.com/cyanheads/obsidian-mcp-server/issues/120)) — `obsidian_delete_note`'s `ctx.requestInput` confirmation needs a stateful session on a 2025-era HTTP client. Under `stateless` the round trip is refused before any vault call, now as a typed `InvalidRequest` carrying `data.reason: "client_capability_missing"` where mcp-ts-core served a bare `isError` text block before 0.13.5. `teardown` closes `ObsidianService`'s undici dispatcher, releasing keep-alive sockets to the Local REST API and Omnisearch.
- **Every `errors[]` reason the service layer raises declares `thrownBy: 'service'`** (path policy, periodic-note routing, ambiguous case matches), and `obsidian_delete_note`'s `cancelled` reason carries `severity: 'notice'` — both are mcp-ts-core 0.13.5/0.13.6 error-contract metadata; the entries stay advertised and thrown exactly as before.

## Changed

- **Tool error text now closes with the terms a caller branches on** — `(reason <reason>)`, joined by ` · ` with `retryable` or `not retryable` where the contract declares it — and drops the `Recovery:` line when the message already states the hint verbatim (mcp-ts-core 0.13.5).
- **A schema-rejected tool call carries `data.reason: "invalid_arguments"`** and a synthesized `Recovery:` hint naming the offending field (mcp-ts-core 0.13.3).
- **Tool arguments pass an ordered pre-validation step** before schema parsing — client-added root keys are dropped, an undeclared key is rewritten to a case-folded match, and a JSON-stringified array is repaired and re-parsed once on failure (mcp-ts-core 0.13.4).

## Fixed

- **`OBSIDIAN_BASE_URL` strips a trailing slash** ([#121](https://github.com/cyanheads/obsidian-mcp-server/issues/121)) — a slash-terminated value doubled the separator on every request path and 404'd the whole vault.
- **A failed request's log cause names the URL that was actually fetched** ([#122](https://github.com/cyanheads/obsidian-mcp-server/issues/122)), so a malformed base URL no longer reads as a clean 404 against a healthy vault. The client-facing `path` and message are unchanged.
- **`obsidian_manage_frontmatter` (`delete`) and `obsidian_manage_tags` refuse to write instead of destroying content** when the note's frontmatter doesn't parse as a mapping or the mutation leaves YAML the emitter can't re-emit — a dangling alias, for instance ([#123](https://github.com/cyanheads/obsidian-mcp-server/issues/123), [#124](https://github.com/cyanheads/obsidian-mcp-server/issues/124)). Both tools declare the new `frontmatter_invalid` reason; nothing is written on refusal, and `obsidian_manage_tags` skips the inline half too under `location: "both"`. `obsidian_replace_in_note` already declared that reason and picks up the re-emit half of the check, so a replacement that strands an alias is refused rather than written.
- **Tag edits mutate an existing `tags:` sequence node in place** ([#123](https://github.com/cyanheads/obsidian-mcp-server/issues/123)) rather than replacing it with a normalized string set, so non-string entries, comments, and untouched item formatting survive.
- **A rewritten frontmatter block keeps the note's own line ending** (LF or CRLF) instead of always emitting LF, and deleting the last key drops only the blank separator lines rather than the body's leading indentation ([#125](https://github.com/cyanheads/obsidian-mcp-server/issues/125)).
- **`obsidian://vault/{+path}` percent-decodes the captured path** ([#132](https://github.com/cyanheads/obsidian-mcp-server/issues/132)) — a note name with a space, non-ASCII character, or literal `%` never resolved before; a malformed escape decodes leniently instead of throwing.

## Security

- **TLS certificate verification is scoped to each request to an `https:` `OBSIDIAN_BASE_URL`** ([#131](https://github.com/cyanheads/obsidian-mcp-server/issues/131)) instead of `OBSIDIAN_VERIFY_SSL=false` setting `NODE_TLS_REJECT_UNAUTHORIZED=0` process-wide on Bun, which disabled certificate verification for every other HTTPS call the process made (a JWKS fetch, for instance). Node's dispatcher option and Bun's per-request `tls` option are both sent on every request, covering both runtimes with no runtime sniffing.
