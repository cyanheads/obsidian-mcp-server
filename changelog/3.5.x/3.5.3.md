# 3.5.3 — 2026-09-13

## Changed

- **Bun engines floor raised to `>=1.4.0`** — required since mcp-ts-core 0.12.9.
- **Development skills moved from `skills/` to `framework-skills/`** — Claude Code and Codex auto-load a plugin's root `skills/`, so installing this server's plugin no longer loads its development skills into the installing agent ([cyanheads/mcp-ts-core#428](https://github.com/cyanheads/mcp-ts-core/issues/428)).

## Fixed

- **An empty or whole-value `${...}` env value now reads as unset** — `OBSIDIAN_REQUEST_TIMEOUT_MS=''` starts with the default timeout and `OBSIDIAN_API_KEY='${OBSIDIAN_API_KEY}'` fails at startup as a missing key rather than as a format error; the server's own redundant empty-string guards on `baseUrl`/`omnisearchUrl` were removed as a result ([cyanheads/mcp-ts-core#427](https://github.com/cyanheads/mcp-ts-core/issues/427)).
- **A cancelled single-request HTTP POST's SSE stream now closes immediately**, instead of waiting for keep-alive or session expiry ([cyanheads/mcp-ts-core#401](https://github.com/cyanheads/mcp-ts-core/issues/401)).
- **The `.mcpb` bundle now passes the settings entered at install to the server** — `manifest.json`'s `mcp_config` referenced `${OBSIDIAN_*}`, which the MCPB host does not substitute, so the server received the literal placeholder text; every option is now wired as `${user_config.<key>}`.
- **Plugin installs no longer blank out exported env vars** — `.claude-plugin/plugin.json` and `.codex-plugin/mcp.json` set `OBSIDIAN_API_KEY`/`OBSIDIAN_BASE_URL` to `""`, replacing a value the user had exported; the Claude Code plugin now declares them as `userConfig` options, and the Codex plugin forwards them through `env_vars`.
