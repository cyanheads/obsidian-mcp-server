# 3.9.0 — 2026-11-11

## Added

- **The `obsidian-guide` skill**, the server's first published skill, served as `skill://obsidian-guide/SKILL.md` through `createApp({ skills: 'skills' })`. The server `instructions` point at it.

## Changed

- **`obsidian_search_notes` with `mode: "omnisearch"` under `OBSIDIAN_READ_PATHS` or `OBSIDIAN_DENY_PATHS` is rejected as invalid params (-32602)** before any Omnisearch request, the startup probe included. The mode is withheld from the `mode` enum and the tool description, and the output enum `truncatedReason` no longer has `read_scope`. Scoped callers search with `text` or `jsonlogic`. ([#173](https://github.com/cyanheads/obsidian-mcp-server/issues/173))
- **Heading writes below a repeated link definition fail `repeated_link_definition` before any PATCH**, from `obsidian_patch_note` and from `obsidian_append_to_note` and `obsidian_write_note` with `section`. For a section that runs to the end of the note, the repeat must sit above the target heading itself; a repeat inside that last section is not refused. ([#175](https://github.com/cyanheads/obsidian-mcp-server/issues/175))
- **The refusal also covers shapes where no plugin engine would have misplaced the content**: a prepend whose repeat sits inside the target section, and labels the check folds more coarsely than the parser does. On plugin 5.x a heading write now reads the note before the PATCH, so a read of it that fails persistently or with a 4xx fails a write 3.8.0 sent. ([#175](https://github.com/cyanheads/obsidian-mcp-server/issues/175))
- **A request attempt that runs past `OBSIDIAN_REQUEST_TIMEOUT_MS`, headers or body, fails `obsidian_timeout` on Bun and Node.** Bun had no bound; Node bounded neither a trickled body nor a mid-body gap. ([#176](https://github.com/cyanheads/obsidian-mcp-server/issues/176))
- **A call whose requests together pass max(45 s, `OBSIDIAN_REQUEST_TIMEOUT_MS`) fails `obsidian_timeout`**, e.g. a deep `obsidian_list_notes` walk of a large vault. ([#176](https://github.com/cyanheads/obsidian-mcp-server/issues/176))
- **`OBSIDIAN_REQUEST_TIMEOUT_MS` above 2147483647 fails at startup.**
- **A connection dropped mid-body fails `obsidian_unreachable` and is retried on GET, PUT, and DELETE.** On Bun it surfaced raw runtime text with no retry. ([#176](https://github.com/cyanheads/obsidian-mcp-server/issues/176))
- **A scoped `text` search is searched once.** Later pages come from the stored hit list, kept up to 5 minutes past the last page read and 32 Mi characters across walks, and show the first page's snapshot. A walk is stored only when the hits run past the page being served. ([#177](https://github.com/cyanheads/obsidian-mcp-server/issues/177))
- **The Omnisearch-mode `matches`, `excerpt`, and `score` descriptions are corrected**, and `omnisearch_unreachable` now covers a timeout and a non-2xx answer. `tools/list` declares it only where the mode is offered. ([#173](https://github.com/cyanheads/obsidian-mcp-server/issues/173))
- **The `obsidian_list_tags` description gains JSONLogic tag-matching examples**, and the server `instructions` point at the `obsidian-guide` skill.

## Fixed

- **A call waiting on the plugin-version read another call started no longer fails when that other call is cancelled**; it reads the version itself.
- **The did-you-mean, ambiguous-path, and case-variant path suggestions in `content[]` render as code spans.**
- **Creating a heading under an existing ancestor finds that ancestor in time linear in the note.**

## Security

- **Under `OBSIDIAN_READ_PATHS`, Omnisearch ranked and selected its results over the whole vault**, so notes outside the scope changed what a scoped caller saw. The mode is now withheld under a read scope. ([#173](https://github.com/cyanheads/obsidian-mcp-server/issues/173))
